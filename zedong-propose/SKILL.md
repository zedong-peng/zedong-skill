---
name: zedong-propose
description: How the user wants a new idea turned into a proposal they decide on. Use when the user brings a new idea or direction, or before you propose a new project, tool or line of work.
---

Every new idea gets its own proposal, and the user decides whether it goes ahead. Judge it with zedong-think. Once the user approves it, it runs as a line under zedong-research.

Find out what already exists before proposing anything: products, open-source projects, leaderboards, papers and blogs. If something the user already has makes the problem disappear, such as an input method they are happy with, say so plainly and recommend not doing it.

The user's work is research, which they see as their leverage. Any algorithmic question qualifies. Building a tool or benchmarking products does not, unless it answers a research question.

Keep a proposal short. It states the question, what already exists and the gap that leaves, and ends with a plain recommendation.
